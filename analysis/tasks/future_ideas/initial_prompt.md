# Goal

Read the entire repository and understand its architecture, current capabilities, design philosophy, and overall direction before proposing any changes.

Do not perform a generic code review or produce a list of random feature requests.

Your objective is to infer the vision behind this project and identify the most natural directions in which it could evolve.

## Immediate Opportunities

Identify the improvements, missing features, architectural refinements, or quality-of-life enhancements that naturally follow from the current implementation.

Focus on things that could realistically be developed next.

Write your findings to:

`<OUTPUT_DIRECTORY>/immediate-opportunities.md`

For each proposal include:

* Title
* Why it fits the project
* Expected value
* Estimated implementation complexity
* Suggested implementation order

---

## Long-Term Directions

Think beyond the current implementation.

Based on the existing architecture and philosophy, identify the major directions this software could evolve toward over the coming years.

Avoid proposing unrelated ideas; every direction should emerge naturally from the current project.

Write your findings to:

`<OUTPUT_DIRECTORY>/long-term-directions.md`

For each direction include:

* Vision
* Why it is a natural evolution of the project
* What architectural changes it would require
* Potential benefits
* Potential risks

---

Before writing the reports, briefly explain (to yourself through reasoning) what you believe the purpose and long-term vision of this software are. Use that understanding to guide every recommendation.

Prioritize coherence with the project's philosophy over the number of ideas generated.
